# 改哪里能改什么 · 灵活修改指南

这份初跑版的核心原则：**配置驱动 + 逻辑与数值分离 + 服务端权威**。
绝大多数调整只改 `configs/*.json`，不动代码；代码只负责跑逻辑。

---

## 一、配置在哪里

| 文件 | 管什么 | 典型改动 |
|------|--------|----------|
| `configs/classes.json` | 6 职业属性、等级成长、转职树、转职门槛 | 改职业强度、升降转职等级、加职业 |
| `configs/skills.json` | 15 个技能的威力/冷却/类型、技能槽数 | 调技能伤害、改 CD、增删技能 |
| `configs/equipment.json` | 4 装备槽、5 品级、强化成本、转职装备换算系数 | 调强化成本、改品级倍率 |
| `configs/monsters.json` | 4 种怪物属性/经验/金币、刷新权重、保底 | 调怪物强度、掉落率 |
| `configs/economy.json` | 离线/体力/战斗/掉落/地图/分辨率/多人 | 改离线速率、封顶时长、地图尺寸 |
| `configs/worlds.json` | 6 世界、点位坐标、通道、刷新冷却 | 加地点、改坐标、调刷新 |

> 客户端 `client/assets/configs/` 下有同步副本。改完配置后：
> - 服务端：重启 `zjcs-server`（或调用 `game.Reload` 热重载）
> - Web 验证页：刷新浏览器即可看到新配置
> - Cocos：把 configs 放进 `assets/resources/configs`

## 二、常见修改示例

### 1. 让升级更快
改 `classes.json` 的 `levelGrowth`：
```json
"expBase": 60 → 30,   "expGrowth": 1.18 → 1.12
```
（升级所需经验 = expBase × expGrowth^(level-1)，调小即加速）

### 2. 提高离线收益 / 延长封顶
改 `economy.json` 的 `idle`：
```json
"maxHours": 8 → 12,   "expPerMinute": 6 → 10
```
（8h 封顶是设计承诺，改动前先过 playtest）

### 3. 让某职业更强
改 `classes.json` 对应职业的 `bonus`：
```json
"mage": { "atk": 1.30 → 1.5 }
```

### 4. 改技能伤害/冷却
改 `skills.json` 对应技能：
```json
{ "id": "fireball", "power": 1.8 → 2.5, "cd": 3 → 5 }
```

### 5. 加一种新怪物
在 `monsters.json` 的 `monsters` 数组追加一条；若有对应像素动画帧，放到 `client/assets/resources/monsters/` 并在 `animation_spec.json` 登记。
服务端 `MonsterByID` 自动识别，无需改代码。

### 6. 加一个新世界
在 `worlds.json` 的 `worlds` 数组追加一个对象，填 spawns 点位；背景图放 `resources/backgrounds/`。
链式/捷径拓扑按地图设计 v0.4 的 2.5 节规则生成（环数 ≥6）。

### 7. 后续加全新系统（如公会/战令）
- **零改表方案**：直接往存档的 `ext_data` 扩展位写 key-value，刷新后自动还原。
- **正式建表方案**：在 `server/schema.sql` 加 CREATE TABLE，`schema_meta.version` +1；Go 侧 `store.PlayerState` 加对应字段。

## 三、代码模块边界（需要动逻辑时看这里）

| 模块 | 文件 | 职责 | 什么时候改 |
|------|------|------|-----------|
| 配置加载 | `server/internal/game/config.go` | 读 JSON、按 ID 查询 | 加新的配置类型时 |
| 属性计算 | `server/internal/game/stats.go` | 职业×等级×装备、转职装备换算 | 改属性公式时 |
| 权威战斗 | `server/internal/game/battle.go` | 技能队列、回合结算、掉落 | 改战斗规则时 |
| 离线结算 | `server/internal/game/idle.go` | 服务端时间戳、8h 封顶 | 改结算规则时 |
| 存档结构 | `server/internal/store/state.go` | 11 张逻辑表结构 | 加正式字段时 |
| 存档变更 | `server/internal/store/mutate.go` | 战斗/离线奖励合并、升级、战力刷新 | 改入账规则时 |
| 磁盘存档 | `server/internal/store/disk.go` | standalone 模式原子读写 `data/saves/` | 换存储后端时 |
| HTTP API | `server/internal/net/api.go` | standalone 模式端点（含落库） | 加接口时 |
| Nakama RPC | `server/nakama_module/main.go` | 生产模式 RPC 注册 + Storage 读写 | 加 RPC 时 |

> 存档后端可替换：`disk.go`（本地文件）与 Nakama 模块的 Storage 读写共用 `store.PlayerState` + `mutate.go`，
> 换后端只需替换 Save/Load 两处，游戏逻辑零改动。

客户端（TypeScript）：

| 模块 | 文件 | 职责 |
|------|------|------|
| 协议 | `client/assets/scripts/core/Protocol.ts` | 消息类型与数据结构（与服务端对齐） |
| 配置 | `.../core/ConfigManager.ts` | 加载/热更新 JSON |
| 网络 | `.../core/NetworkManager.ts` | WS/WSS、心跳、退避重连 |
| 状态 | `.../core/GameState.ts` | 服务端快照镜像 |
| 启动 | `.../core/Bootstrap.ts` | 读连接配置→连接→登录→快照 |
| 战报表现 | `.../systems/BattlePresenter.ts` | 逐回合演出（只读回显） |
| 大世界 | `.../systems/ExploreController.ts` | XY 走位、遇怪选择 |

## 四、两种运行模式

| 模式 | 启动 | 用途 | 服务端 |
|------|------|------|--------|
| **standalone**（默认，初跑用） | `bash scripts/start.sh` / 双击 `启动初跑.bat` | 立即跑通属性/战斗/离线，浏览器打开 `web/index.html` 验证 | Go HTTP :8080 |
| **Nakama**（联网完整） | `cd server && docker compose up -d` | 账号/Storage/匹配/实时多人；公网内测配 Cloudflare 隧道 | Nakama :7350 |

两种模式共用 `internal/game` 的权威逻辑，改一次两边生效。

> **注意**：Nakama Go 插件（`nakama_module/`）需用与 Nakama 相同的 Go 版本编译为 `.so`，
> 且启用 `//go:build nakama` 标签：`go build -tags nakama -buildmode=plugin -o zjcs.so .`

## 五、联机（公网内测）

1. 本地起 Nakama：`cd server && docker compose up -d`
2. 开 Cloudflare 临时隧道：`cloudflared tunnel --url http://localhost:7350`
3. 拿到 `https://xxx.trycloudflare.com`，生成 `connection_info.json`：
```json
{ "host": "xxx.trycloudflare.com", "port": 443, "useSSL": true,
  "serverKey": "你的key", "httpBase": "https://xxx.trycloudflare.com" }
```
4. Cocos 客户端 `Bootstrap.start(info)` 读取该文件连接。
地址每次启动会变，属临时隧道正常现象，更新 `connection_info.json` 即可。

**安全**：server key 与数据库密码用随机值，别写进材料包；7351 控制台不暴露公网。
